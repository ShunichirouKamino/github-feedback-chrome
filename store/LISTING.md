### 説明

```
開発中・検証中の Web アプリを触りながら、気づいたことをその場で GitHub Issue にするための拡張機能です。
コードではなく「動いている画面」を見てレビューすることが増えた開発チーム向けに作りました。

■ 使い方
1. Ctrl+Shift+1（または拡張アイコン）でコメントモードに入る
2. 気になる要素をクリック、または範囲をドラッグして選択
3. コメントを書いて「Issue を開く」
4. GitHub の Issue 作成画面に、本文とスクリーンショットが自動で入る。内容を確認して作成

■ Issue に自動で入る情報
・スクリーンショット（選択範囲を赤枠で強調。選択範囲の周辺だけにも設定可能）
・ページの URL、環境名（local / stg など）、画面サイズ、ブラウザ、日時
・選択した要素の CSS セレクタとテキスト
・登録したホストでは、コンソールのエラー・警告と失敗した通信、HTML の抜粋（含めるかは起票時に選択）
AI エージェントに Issue を渡しても修正箇所を特定しやすい形で記載します。

■ 起票先の振り分け
localhost:*、*.stg.example.com のようなホストのパターンごとに、起票先リポジトリ・環境名・ラベルを設定できます。GitHub Enterprise Server にも対応しています。

■ プライバシーとセキュリティ
・GitHub のトークンは使いません。ログイン中のブラウザで GitHub の画面を開き、Issue の作成は利用者自身が行います
・URL・ログ・HTML に含まれるトークン、パスワード、署名付き URL などはマスクしてから記載します
・本文は URL に載せず、ブラウザの履歴に残りません
・起票先が公開リポジトリの場合は警告します
・開発者や第三者のサーバーには一切データを送信しません

※ 本拡張機能は GitHub, Inc. とは関係のない非公式のツールです。
```

## プライバシーへの取り組み（Privacy practices）タブ

### 単一用途の説明

```
表示中の Web ページにコメントを付け、スクリーンショットとページの情報を添えて GitHub の Issue 作成画面に入力すること。
```

### 権限が必要な理由

| 権限 | 入力する理由 |
|---|---|
| activeTab | 利用者がアイコンまたはショートカットを押したタブに、コメント入力用の UI を表示し、そのタブのスクリーンショットを撮影するために使用します。 |
| scripting | コメント入力用の UI の表示、GitHub の Issue 作成画面への本文とスクリーンショットの入力、利用者が登録したホストでのエラー記録用スクリプトの登録に使用します。 |
| storage | 起票先リポジトリなどの設定と、Issue 作成画面に入力するまでの本文・スクリーンショットの一時保存に使用します。 |
| ホスト権限（github.com / api.github.com） | github.com の Issue 作成画面に本文とスクリーンショットを入力するため、および起票先リポジトリが公開かどうかを GitHub API で確認するために使用します。 |
| ホスト権限（optional: すべてのサイト） | 必須ではありません。利用者が設定画面で登録したホスト（例: localhost、検証環境のドメイン）に限り、利用者の許可を得て、コンソールのエラーと失敗した通信を記録するために使用します。GitHub Enterprise Server を使う場合は、そのホストへの入力にも使用します。 |

### リモートコード

- 「いいえ、リモートコードを使用していません」を選ぶ（すべてのスクリプトはパッケージに含まれています）

### データの使用

収集・使用するデータとしてチェックするもの:

- [x] ウェブ履歴（起票時に表示しているページの URL を Issue に記載するため）
- [x] ウェブサイトのコンテンツ（スクリーンショット、選択した要素のテキスト・HTML の抜粋、コンソールのエラーを Issue に記載するため）
- それ以外（個人を特定できる情報、健康、財務、認証情報、個人的な通信、位置情報、ユーザーのアクティビティ）はチェックしない

次の 3 つの宣誓にはすべてチェックする:

- [x] 承認されている用途以外で、ユーザーデータを第三者に販売、転送しない
- [x] アイテムの単一用途と関係のない目的で、ユーザーデータを使用、転送しない
- [x] 信用力を判断する目的または融資目的で、ユーザーデータを使用、転送しない

## 審査で指摘されやすい点

- **名前に "GitHub" を含む**: 概要と説明に「GitHub 非公式」と明記し、ロゴは使っていません。それでも商標やなりすましで指摘された場合は、名前を「Issue Feedback for GitHub」などに変更して再申請します。
- **optional のすべてのサイト権限**: 上の理由欄のとおり、利用者が登録したホストだけに許可を求める設計であることを説明します。
